WASD keys make things more fun!

Many of us grew up playing games on computers, using the keyboard to move things around. It is time for us to learn a webpage can read the keyboard

There are a number of different ways to detect the keyboard. Remember how Javascript uses events, such as onclick, onload, and onchange? Well, there are even more options for reading keypresses:

  • window.addEventListener("keydown", codeToRun) will detect when any key has pressed, even if the key has not been raised, including non-symbol keys
  • window.addEventListener("keyup", codeToRun) will detect when any key has been released, including non-symbol keys, but it often feels delayed and sluggish
  • window.addEventListener("keypress", codeToRun) Deprecated, meaning it is functional, but no longer used.

Most Javascript programs use "keydown".

Listening to the window

In Javascript, the window refers to the whole web browser. (In fact, window actually contains all the code, actions, and data of everything that happens in a browser, but more on that later.)

You can't attach "keydown" to just any id. For example: document.getElementById('anyOldId').addEventListener("keydown", codeToRun); will not work. We have to attach onkeydown to the window.

The steps for reading a keystroke are:

window.addEventListener("keydown", keydownFunction);
1. create a listener that looks for a key press, and tells it what function to run
note that keydown is inside the parentheses.

var unicodeNumber = event.which    or   var unicodeNumber = event.key;
2. store which key has been pressed
event.key and event.which are hidden variables your browser uses to stores information about what key has been pressed
event.key gives the string (text) version of the pressed key
event.which give the unicode number, which is easier for programs to compute

//do something interesting with the unicode number
3. often there will be if...else statements here to do different things for different unicode numbers
}
